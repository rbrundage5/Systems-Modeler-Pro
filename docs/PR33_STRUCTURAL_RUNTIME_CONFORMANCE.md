# PR33 Structural Runtime Conformance Matrix

PR33 qualifies a deterministic SysML structural runtime against the repository's current SysML 1.x metamodel. `QUALIFIED` means the stated boundary is enforced by automated semantic tests; it is not a claim of OMG or vendor certification. Concepts that the current metamodel cannot represent without guessing remain `PARTIAL` or `UNSUPPORTED`.

| Concept | Status | Qualified boundary / validation | Known limitation |
| --- | --- | --- | --- |
| Block | QUALIFIED | A Block remains a classifier definition; a configured root occurrence or typed structural usage materializes a `RuntimeInstance`. | Classifier behavior selection beyond the existing stable behavior references remains later integration work. |
| PartProperty | QUALIFIED | Composite Parts recursively materialize owned runtime occurrences with deterministic owner/path/ordinal identity and cycle detection. | Dynamic population changes during execution are not introduced in PR33. |
| ReferenceProperty | QUALIFIED | References are non-owning and resolve only through explicit runtime binding decisions; they never create owned structure. Duplicate binding decisions are rejected instead of using first-match behavior. | The authored metamodel does not yet persist a complete configuration/reference-binding model. |
| Multiplicity | QUALIFIED | Runtime population is checked against authored lower/upper bounds; unbounded upper multiplicity is not arbitrarily materialized without an explicit population decision. Duplicate population decisions are rejected. | Runtime creation/destruction after initialization is deferred. |
| ValueProperty | QUALIFIED | Authored defaults initialize independently per runtime occurrence and are addressed by runtime instance plus semantic property. Numeric/boolean defaults use the shared bounded expression parser; serialized quoted text defaults are normalized to their semantic text value instead of retaining JSON quoting. Invalid authored defaults block runtime construction, and an occurrence-scoped runtime value takes precedence over the legacy global fallback. | Full unit conversion / dimensional analysis belongs to Parametric work. |
| ValueType | PARTIAL | Runtime value metadata retains represented type/unit identity and assignment/flow checks use represented semantic types. | The current runtime is not a complete quantity calculus or ValueType conversion engine. |
| Generalization / inherited features | PARTIAL | Effective inherited structural features are collected deterministically and ambiguous same-name inherited definitions are rejected. | The current metamodel lacks explicit redefinition/subsetting links needed to qualify full UML/SysML feature-redefinition semantics. |
| InstanceSpecification | PARTIAL | A typed authored InstanceSpecification can be used as a configured/root runtime occurrence where current fields are sufficient. | Complete Slot/defining-feature/value override semantics are not represented by the current metamodel. |
| Slot | UNSUPPORTED | No execution semantics are invented. | Current metamodel lacks complete Slot defining-feature/value semantics. |
| Port | QUALIFIED | Runtime Ports are semantic endpoints owned by a specific runtime occurrence; diagram anchors are not runtime identity. | Additional specialized port/profile semantics remain bounded by what the current metamodel represents. |
| ProxyPort | QUALIFIED | Proxy and Full Ports remain distinct; ProxyPort typing is validated against InterfaceBlock and the runtime does not create a standalone behaving part for a proxy. | Complete interface-feature conjugation semantics are limited to fields represented by the current profile. |
| FullPort | QUALIFIED | FullPort remains distinct from ProxyPort and is materialized as an instance-owned semantic interaction endpoint. | Full independent port-part behavior is limited to the current classifier/behavior model. |
| FlowPort | NOT_APPLICABLE | PR33 does not silently translate legacy FlowPort semantics into ProxyPort semantics. | Only applicable if the active project profile retains a qualified legacy FlowPort representation. |
| InterfaceBlock | QUALIFIED | Used as the required ProxyPort contract type where represented; flow contracts are derived from modeled interface features. | Interface feature subsets not present in the metamodel cannot be inferred. |
| FlowProperty | QUALIFIED | Represented flow direction/type participates in source/target signal/item compatibility checks, including conjugation where represented. Compatibility is directional and does not accept an invalid inverse conformance relation. | Full physical quantity/continuous-flow simulation is outside PR33. |
| Connector | QUALIFIED | Runtime links resolve semantically from owning context and endpoint property paths, never from diagram geometry; endpoint failures block initialization with readable diagnostics. | Association-typed Connector semantics are partial because authored Connector-to-Association typing is not fully represented. |
| Nested Connector End / property path | QUALIFIED | Nested endpoint paths resolve through runtime Part/Reference occurrences with deterministic qualified paths; duplicate runtime paths and deterministic-ID collisions are rejected. | Paths requiring unavailable redefinition/subsetting metadata remain outside the qualified boundary. |
| Association-typed Connector | PARTIAL | Existing endpoint type compatibility is preserved where represented. | The current authored Connector metamodel does not carry a complete Association typing reference, so PR33 does not fabricate it. |
| AssociationBlock-typed Connector | PARTIAL | Existing structural endpoint compatibility is preserved. | Complete AssociationBlock connector-property runtime semantics require explicit connector typing not currently available. |
| Assembly connector | QUALIFIED | Internal endpoint pairs resolve to the correct runtime occurrences/Ports and participate in indexed runtime transport. | Rich operation semantics over the connection are PR34 scope. |
| Delegation connector | QUALIFIED | Boundary-to-internal semantic endpoints resolve without using diagram nesting/geometry. | Advanced connection-point semantics not represented in the current profile are not inferred. |
| ItemFlow | QUALIFIED | Conveyed item IDs, authored direction, and represented source/target flow contracts constrain runtime transport. Incompatible conveyed types/directions are rejected using directional classifier conformance. | Continuous material/energy flow solving is not part of PR33. |
| Signal addressing | QUALIFIED | Structural routing produces deterministic runtime-instance/Port destinations through the shared event architecture; unconnected instances do not receive the signal. | Complete Signal/Operation orchestration remains PR34. |
| Reception boundary | QUALIFIED | Where a Reception is represented on the receiving classifier, delivery validates directional Signal compatibility before routing. | Full triggered Operation behavior is deferred to PR34. |
| Activity runtime-instance context | QUALIFIED | PR31 Activity execution can be bound to an explicit runtime occurrence and resolves instance-scoped values/events through the shared `ExecutionSession`. Repeated classifier occurrences are independently selectable and preserve independent ValueProperty state. | Full operation-call dispatch across structural endpoints is PR34. |
| State Machine runtime-instance context | QUALIFIED | PR32 State Machine execution, State entry/doActivity/exit, and Submachine execution preserve explicit runtime occurrence context. | EntryPoint/ExitPoint/History limitations remain those explicitly qualified in PR32. |
| Desktop runtime configuration | QUALIFIED | Activity and State Machine execution expose a thin configuration workflow for selecting a structural execution root, previewing the Rust-built runtime graph, choosing a compatible repeated runtime occurrence, and supplying transient multiplicity/reference/InstanceSpecification configuration. Configuration invalidates stale execution sessions and is validated by Rust before execution. | These runtime decisions are transient by design and do not rewrite authored PartProperty multiplicities, ownership, or InstanceSpecifications. |
| Runtime inspection UI | QUALIFIED | UI renders only Rust-produced instance/value/Port/connector/event facts and owns no structural semantics. | This is inspection, not a second model repository or simulator. |
| Authored-model isolation | QUALIFIED | Structural runtime is transient; automated qualification compares authored serialization before/after runtime construction/execution where applicable. | Persisting runtime state back to the authored model would require a separate explicit workflow. |

## Automated qualification evidence

The primary PR33 semantic fixture is `crates/model-core/tests/pr33_structural_runtime.rs`. It includes authored-default normalization and validation, deterministic instance/value construction, structural routing, repeated-classifier runtime selection, duplicate-decision/path rejection, and negative type-conformance cases. `crates/model-core/tests/pr33_activity_instance_context.rs` additionally qualifies two Activity executions of the same classifier against distinct selected runtime occurrences and proves that their ValueProperty state and guard resolution remain independent.

Desktop integration is guarded by `scripts/validate_structural_runtime_integration.py`, registered in both Linux/core and Windows/desktop CI. That contract verifies the shared runtime-selection API, Activity and State Machine configuration commands, thin frontend runtime configuration, and the absence of frontend-owned structural runtime construction/routing semantics.

PR33 remains gated by the existing PR31 Activity and PR32 State Machine suites plus the shared all-nine-family authoring, routing/frame, repository editing, workspace convergence, and Rust-authority/frontend-debt checks. Exact-head Linux/core and Windows/desktop CI must both pass before the matrix is accepted as qualified evidence.

## Professional qualification rule

A concept may be promoted to `QUALIFIED` only when the automated test suite proves the exact boundary above on Linux/core and Windows/desktop CI while PR31 Activity, PR32 State Machine, all-nine-family authoring/editing, routing/frame, repository-editing, and Rust-authority/frontend-debt contracts remain green.
