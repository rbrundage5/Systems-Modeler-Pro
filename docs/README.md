# Documentation entry point

Read documents according to their purpose and recorded baseline. A milestone
contract is useful evidence, but is not a current whole-product completeness claim.

| Need | Read |
| --- | --- |
| Product overview | [Root README](../README.md) |
| Architecture and current layout | [Architecture](ARCHITECTURE.md) |
| ChatGPT Project setup | [Source setup](CHATGPT_PROJECT_SETUP.md) and [brief](CHATGPT_PROJECT_BRIEF.md) |
| Every existing document and disposition | [Review register](DOCUMENTATION_REVIEW.md) |
| Creating import inputs | [Importer input specification](IMPORTER_INPUT_SPECIFICATION.md), PR67 baseline |
| Detailed import history/contracts | [Import qualification](IMPORT_RULES_AND_QUALIFICATION.txt), UPDATE REQUIRED |
| Long-term capability themes | [Roadmap](ROADMAP.md), not current progress |
| Semantic/notation/runtime milestone references | Individual PR/BDD documents listed in the review register |

Historical PR scope guards and unchecked checklists apply to their original
milestones. They do not instruct a new agent to resume an old branch or restrict a
newly authorized task. Read relevant current code and tests before using a milestone
claim as present-day evidence. No agent configuration is installed by this cleanup.
